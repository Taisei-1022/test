# 本体セッションへの依頼：挑戦状とSNS経由の来訪を数えられるようにする

マーケティング担当（marketing/ の別セッション）からの依頼です。SNS発信の効果を測るために、アプリ側で数を数える仕組みを入れてほしいです。

## 背景
- マーケの一番大事な数字を「1週間に送られた挑戦状の数」にした（計画：`marketing/plan.html`）。
- 調べた範囲では、今アプリで記録しているのは `scores`（点数の登録＝遊ばれた回数）だけ。
  - 挑戦状を送った回数、挑戦状リンクが開かれた回数、どのSNSから来たか（`?from=tiktok` など）は記録されていない。
  - アクセス解析（Google アナリティクス等）も入っていない。GitHub Pages なのでサーバーのアクセス記録もない。

## 数えたいこと（優先順）
1. **挑戦状リンクから開かれた回数**：`play.html` が `ch=` 付きで開かれた時
2. **挑戦状を受けて遊んだ回数**：`ch=` 付きで開いた人が、ゲームオーバーまで遊んだ時（点数の登録時）
3. **挑戦状を送った回数**：共有画面の「🔥 挑戦状を送る」を押し、`navigator.share` が完了した時（キャンセルは除く）、またはコピーに成功した時。※実際に相手に届いたかはブラウザからはわからないので、「送る操作が完了した数」とする
4. **どこから来たか**：URL の `from=`（tiktok / youtube / x / instagram）を最初に開いた時に覚えておき（sessionStorage 等）、上の1〜3と「ゲームを遊んだ」記録に付ける。挑戦状で届いたリンクには `from=challenge` 相当が付くとよい

## 見たい形
- 管理画面に「週ごとの数」：挑戦状を送った数・挑戦状から開かれた数・挑戦状から遊んだ数・来た場所ごとの来訪数と遊んだ数
- 週の区切りは火曜〜月曜（マーケのふり返りが火曜のため）。難しければ月〜日でもよい

## お願いしたい条件
- 個人がわかる情報は記録しない（名前・IP・端末の識別子は不要。数だけわかればよい）。必要ならプライバシーポリシーの追記も
- 書き込みは記録の追加だけ許可し、読み出しは運営だけ。いたずらで大量に書き込まれないよう、既存の rate_limit と同じ考え方で制限
- 計測が失敗してもゲームや共有の動きは止めない
- アプリ外の解析サービスは入れない方向（入れるなら事前に相談）

## マーケ側の対応
- SNSのプロフィールに置くリンクを媒体ごとに `https://vappa.app/arcade/?from=tiktok` のように変える（`from=` の名前はこちらに合わせて決めてもらってよい）
- 入ったら、週1回（火曜）その数を記録表に写す

以上、実装の方法はお任せします。終わったら、`from=` の値の一覧と管理画面のどこで見られるかを教えてください。
