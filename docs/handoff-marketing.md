# 申し送り：Vappa のマーケティング（ショート動画・SNS）

別セッションで並行して進めてもらうための引き継ぎ。アプリ本体の開発は別のセッションが同時に進めているので、**下の「触らないもの」を必ず守る**こと。

## 1. プロダクトの要点
- **Vappa（https://vappa.app/arcade/）**：AIと会話するだけで、スマホ用のミニゲームを作って公開・共有できる PWA。
- 方向性は「**送り合うくそげー**」。くだらないけど、つい友だちに送りたくなるゲームを作って送り合う場所。
- 主な仕組み：
  - **挑戦状**：ゲームオーバー後に、自分の点数を添えたリンクを送れる（「◯◯の挑戦：120点。抜ける？」）
  - **ランキング**：ゲームごと
  - **公式ゲーム**：9本（満員電車、ひとながれシティ、松島など）。ほかにユーザー作品がある
- 収益：作るのは無料。将来、盛る・目立たせる機能を有料にする予定（Stripe は名義を相談中）。AdSense は再申請の準備中。
- 運営者（ユーザー）は、作業をスマホと PC で行う。**返答は日本語で、専門用語を避けて**書く。

## 2. このセッションでやること（優先順）
1. **運営が出すショート動画（A）**：TikTok・YouTube ショート・X 向け
   - 縦長 9:16（1080×1920）、15〜30秒の mp4
   - 素材の案：
     - 公式ゲームや人気ゲームの自動プレイ録画
     - 「AIと話して30秒でゲームができる」様子（チャット → 完成 → 遊ぶ）
     - 「この点数抜ける？ vappa.app」の締め
   - 字幕を入れる（音なしで見られる前提）。音楽は著作権フリーのものだけ使う。
   - 投稿文とハッシュタグの案もセットで出す。
   - **投稿はユーザーが手で行う**（自動投稿は審査・有料APIが必要なので、今はやらない）。
2. **SNS 運用の方針案**：X アカウントの使い方、投稿の頻度、ネタの型（新作紹介／挑戦状チャレンジ／作る過程）。
3. **アプリ内の「プレイ動画を保存・共有」機能（B）は提案まで**。アプリ本体のコード変更になるので、実装は本体側のセッションでやる。仕様案（ゲームオーバー後に直前15秒を録画、vappa.app の透かし、挑戦状リンクと組み合わせる）を文書にまとめるところまでにする。

## 3. 使えるもの
- **自動プレイ**：`tests/gamegen-eval/` に Playwright で自動で遊ばせる仕組みがある。
  - `run.js`：採点
  - `elements.js`：時間を早回しして遊ばせる
  - Playwright の録画機能（`recordVideo`）と組み合わせればプレイ動画が撮れる。
  - Chromium はインストール済み。`playwright install` はしないこと。
- **ゲームの実物**：
  - 公式：`arcade/games/<id>/`
  - 評価用：`arcade/eval/*.html`（10本。「もぐらたたき」「シューティング」など、要素を盛った版）
  - 本番の作品は https://vappa.app/arcade/play.html?game=<id> で開ける。
- **ffmpeg** はこの環境に入っていない。必要なら入れる。
- **ネットワークの注意**：この環境のブラウザは、プロキシの証明書を信頼しない。本番サイトを Playwright で開く時は、`context.route` で Node の `fetch` を通して中継すると表示できる（TLS の検証は無効にしないこと）。

## 4. 触らないもの（本体のセッションが同時に編集中）
- `arcade/` 以下のアプリ本体：`index.html`、`play.html`、`manage.html`、`admin.html`、`js/*`、`css/*`、`sw.js`
- `arcade/supabase/`（サーバーとデータベース）、`.github/workflows/`
- 作業は **`marketing/` フォルダの中だけ**で行う（動画・台本・投稿文・方針メモ）。
- 大きな動画ファイルはリポジトリに入れすぎない（1本数MBまで、または外部に置く）。

## 5. Git のルール
- ブランチは `claude/railway-switching-game-4p5ijn`（本体と同じ）。push の前に必ず `git pull --rebase origin claude/railway-switching-game-4p5ijn` を実行する。
- コミットメッセージ・コード・文書に、AIのモデル名を書かない。
- PR は作らない（頼まれた時だけ）。
- APIキーや管理者のパスワードを、チャットやファイルに書かない。

## 6. 進め方の期待値
- まず動画を1本作って、ユーザーに見せて方向性を確認する（いきなり大量に作らない）。
- 方向性が決まったら、ゲームごとのシリーズとして増やす。
